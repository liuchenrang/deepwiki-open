# 缓存机制深度分析：文件级别精确度

## 一、双层缓存架构

### 1.1 LocalDB 缓存（文件级别）

**位置**：`/root/.adalflow/databases/{repo}.pkl`

**内容**：
```python
{
    'transformed_docs': List[Document],  # 文档列表
    'commit_hash': str,                  # Git commit hash
    'metadata': dict
}
```

**Document 结构**：
```python
Document(
    text="文件内容...",
    vector=[1024 维浮点数],
    meta_data={
        'file_path': '/ywmall/bz/grade.php',  # 文件路径
        'type': 'code',
        'is_code': True,
        ...
    }
)
```

**精确度**：✅ **文件级别**
- 每个文档都包含 `file_path`
- 可以精确识别每个文件的变更
- 可以单独过滤每个文件的文档

---

### 1.2 DashScope 缓存（项目级别）

**位置**：`./embedding_cache/dashscope_{repo}_Embedder_dashscope_embeddings.pkl`

**内容**：
```python
List[EmbedderOutput]  # 批次输出列表
```

**EmbedderOutput 结构**：
```python
EmbedderOutput(
    data=[
        Embedding(
            embedding=[1024 维向量],
            index=0
        ),
        Embedding(
            embedding=[1024 维向量],
            index=1
        ),
        ...
    ],
    error=None
)
```

**精确度**：❌ **项目级别**
- 不区分文件
- 包含所有批次的向量结果
- 只要输入文本数量或顺序变化，缓存就会失效

### 2.3 DashScope 缓存失效机制

**问题**：DashScope 缓存是**项目级别**的，不是文件级别

**缓存文件路径**：
```python
# dashscope_client.py:746
self.cache_path = f'./embedding_cache/{embedding_cache_file_name}_{self.embedder.__class__.__name__}_dashscope_embeddings.pkl'

# data_pipeline.py:439, 443
cache_suffix = repo_name
embedding_cache_file_name = f"{embedder_type}_{cache_suffix}"
# 例如：dashscope_bz_Embedder_dashscope_embeddings.pkl
```

**缓存内容**：
```python
# dashscope_client.py:766-797
if os.path.exists(self.cache_path):
    with open(self.cache_path, 'rb') as f:
        embeddings = pickle.load(f)  # 加载所有批次的向量

    # 验证缓存的完整性
    cache_is_valid = True
    for batch_idx, batch_output in enumerate(embeddings):
        if batch_output.error:
            cache_is_valid = False
        if not batch_output.data:
            cache_is_valid = False

    if cache_is_valid:
        log.info(f"✅ Loaded cached DashScope embeddings")
        return embeddings  # 返回所有向量
```

**缓存失效条件**：
1. **文件数量变化**：`len(input) != len(cached_embeddings)`
2. **文件顺序变化**：输入文本的顺序与缓存不一致
3. **缓存文件损坏**：某些批次有错误或空向量

**关键问题**：
```
场景：项目有 10 个文件，其中 1 个文件变更

❌ 当前实现（问题）：
1. LocalDB 识别出 1 个文件变更
2. 只将 1 个文件传入 data_transformer
3. data_transformer 内部检查 DashScope 缓存
4. 缓存文件包含的是 10 个文件的向量
5. 输入只有 1 个文件
6. len(input) != len(cache) → 缓存失效！
7. 重新调用 DashScope API 生成这 1 个文件的向量

✅ 优化后（建议）：
1. 为每个文件单独生成缓存
2. 或者，只对未变更的文件使用缓存
```

## 五、缓存机制的局限性

### 5.1 DashScope 缓存的局限

**问题 1：项目级别，不是文件级别**


**影响**：
- ❌ 1 个文件变更 → DashScope 缓存失效

- ✅ 未变更的文件使用 LocalDB 缓存

**实际效果**：
- 虽然缓存失效，但只处理变更的文件
- 不会对未变更的文件重新生成向量
- 所以性能影响有限

**问题 2：缓存验证不完整**


**缺少的验证**：

## 六、性能优化建议

### 6.1 优化 DashScope 缓存（文件级别）

**当前实现**：
```python
# 项目级别缓存
cache_file = "./embedding_cache/dashscope_bz_Embedder_dashscope_embeddings.pkl"
```

**优化方案**：
```python
# 文件级别缓存
cache_file = f"./embedding_cache/dashscope_bz_{file_hash}_cache.pkl"
```

**实现思路**：
```python
def get_file_cache_key(file_path: str, content: str) -> str:
    """生成文件的缓存 key"""
    import hashlib
    content_hash = hashlib.md5(content.encode()).hexdigest()
    return f"{file_path}_{content_hash}"

# 每个文件单独缓存
for file_path, file_content in files.items():
    cache_key = get_file_cache_key(file_path, file_content)
    cache_file = f"./embedding_cache/dashscope_{cache_key}.pkl"

    if os.path.exists(cache_file):
        vector = load_from_cache(cache_file)
    else:
        vector = call_dashscope_api(file_content)
        save_to_cache(cache_file, vector)
```

**优势**：
- ✅ 文件级别的精确缓存
- ✅ 只重新生成变更文件的向量
- ✅ 未变更文件直接使用缓存

---

### 6.2 优化 LocalDB 缓存（增量保存）

**当前实现**：
```python
# 每次都保存所有文档
save_to_localdb(all_documents)
```

**优化方案**：
```python
# 只保存变更的文档
save_changed_documents_to_localdb(changed_documents)
```

**实现思路**：
```python
def save_incremental(db_path: str, new_docs: List[Document]):
    """增量保存文档"""
    db = LocalDB.load_state(db_path)

    # 获取现有文档
    existing_docs = db.get_transformed_data(key="split_and_embed")
    existing_file_paths = {doc.meta_data['file_path'] for doc in existing_docs}

    # 只保存变更的文档
    new_file_paths = {doc.meta_data['file_path'] for doc in new_docs}
    changed_docs = [
        doc for doc in new_docs
        if doc.meta_data['file_path'] not in existing_file_paths
    ]

    # 合并
    all_docs = existing_docs + changed_docs
    db.save_state(db_path)
```

### 6.3 添加文件级别的缓存验证

**实现思路**：
```python
def validate_file_cache(file_path: str, cached_vector: List[float]) -> bool:
    """验证文件级别的缓存"""
    import hashlib

    # 1. 检查文件是否存在
    if not os.path.exists(file_path):
        return False

    # 2. 计算文件 hash
    with open(file_path, 'r') as f:
        content = f.read()
    content_hash = hashlib.md5(content.encode()).hexdigest()

    # 3. 从缓存文件名读取 hash
    cache_hash = extract_hash_from_cache_name(cache_file)

    # 4. 比较
    return content_hash == cache_hash
```

### 7.2 当前实现的局限

❌ **DashScope 缓存**（项目级别）：
- 不区分文件
- 只要有变更就会失效
- 但实际影响有限（只处理变更文件）

❌ **缓存验证**：
- 只验证向量有效性
- 不验证文件内容变化

---

### 7.3 性能分析

**场景**：100 个文件的项目，其中 1 个文件变更

| 操作 | 当前实现 | 优化后（文件级缓存） |
|------|---------|---------------------|
| Git 检测 | ✅ 1 次 | ✅ 1 次 |
| LocalDB 加载 | ✅ 加载 100 个文档 | ✅ 加载 100 个文档 |
| DashScope API | ✅ 调用 1 次 | ✅ 调用 1 次 |
| DashScope 缓存 | ❌ 失效 | ✅ 未变更文件命中 |
| 向量生成 | ✅ 只生成 1 个文件 | ✅ 只生成 1 个文件 |
| pgvector 更新 | ✅ 删除 1 个，添加 1 个 | ✅ 删除 1 个，添加 1 个 |

**结论**：当前实现的性能已经很好，DashScope 缓存失效的影响有限。

### 7.4 变更场景覆盖

| 场景 | 检测 | 处理 | 缓存 |

### 8.3 故障排查

**问题：向量未更新**
1. 检查 Git commit hash 是否变化
2. 检查是否自动 commit
3. 检查 files_to_reprocess 是否包含该文件
4. 检查 DashScope API 是否调用

**问题：所有文件都重新生成**
1. 检查 current_commit != saved_commit
2. 检查 is_new_repository 是否为 True
3. 检查 LocalDB 是否存在

**问题：DashScope 缓存失效**
1. 检查输入文本数量是否变化
2. 检查缓存文件是否损坏
3. 检查是否有错误向量

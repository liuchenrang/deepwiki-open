## 四、向量生成与缓存机制

### 4.1 DashScope 批次处理

**位置**：`api/dashscope_client.py:821-872`

```python
def batch_embed_with_cache(self, texts: List[str]) -> List[List[float]]:
    """
    批次生成向量，带缓存机制
    """
    # 1. 检查缓存文件
    cache_file = os.path.join(self.cache_path, self.cache_file_name)

    if os.path.exists(cache_file):
        with open(cache_file, 'rb') as f:
            cache = pickle.load(f)

        # 2. 验证缓存有效性
        if len(cache) == len(texts):
            logger.info(f"✅ 使用缓存的向量（{len(cache)} 个）")
            return cache

    # 3. 调用 DashScope API
    all_embeddings = []
    for i in range(0, len(texts), self.batch_size):
        batch = texts[i:i + self.batch_size]
        response = self.client.embeddings.create(
            model=self.model_kwargs["model"],
            input=batch
        )
        all_embeddings.extend([e.embedding for e in response.data])

    # 4. 保存到缓存
    with open(cache_file, 'wb') as f:
        pickle.dump(all_embeddings, f)

    return all_embeddings
```

**缓存文件路径**：
```
./embedding_cache/dashscope_{repo}_Embedder_dashscope_embeddings.pkl
```

## 七、关键问题与解决方案

### 7.1 问题 1：删除后重新导入使用了旧向量

**原因**：
- DashScope 缓存文件未删除
- LocalDB 文件未删除

**解决**：
- ✅ 添加 LocalDB 删除逻辑
- ✅ 添加 DashScope 缓存删除逻辑
- ✅ 支持多种缓存文件命名模式

### 7.2 问题 2：代码修改后向量未更新

**原因**：
- 用户修改了代码但未 commit
- Git 检测比较的是 commit hash

**解决**：
- ✅ 自动 commit 未提交的更改
- ✅ Commit 后再检测变更
- ✅ 增量更新时物理删除旧向量

### 7.3 问题 3：增量更新判断不准确

**原因**：
- `git_changes.is_initial` 判断逻辑有问题
- 应该使用 `is_new_repository` 判断

**解决**：
- ✅ 修改判断条件：
  ```python
  if not is_new_repository and not git_changes.is_initial and git_changes.changes:
      # 增量更新
  ```

  ↓
┌─────────────────────────┐
│ 缓存存在且长度匹配?      │
└─────────────────────────┘
  ↓ Yes         ↓ No
使用缓存        检查 LocalDB
  ↓              ↓
直接使用      ┌──────────────┐
              │ LocalDB存在? │
              └──────────────┘
                ↓ Yes    ↓ No
              使用向量  调用 API
                ↓         ↓
              直接使用  生成并保存
                         ↓
                       保存到缓存
                         ↓
                       使用向量

## 十、总结

### 10.1 核心机制

1. **Git Commit Hash 作为版本标识**
   - 新项目：`saved_commit == "N/A"`
   - 已有项目：`saved_commit == current_commit`
   - 有变更：`saved_commit != current_commit`

2. **三级缓存**
   - DashScope 向量缓存：`./embedding_cache/dashscope_*.pkl`
   - LocalDB 缓存：`/root/.adalflow/databases/{repo}.pkl`
   - pgvector 数据库：持久化存储

3. **增量更新**
   - Git 变更检测
   - 只处理变更文件
   - 物理删除旧向量
   - 合并新旧文档

4. **自动 Commit**
   - 检测未提交更改
   - 自动 `git add .` + `git commit`
   - 确保 commit hash 更新

### 10.2 关键文件

- `api/api.py` - API 端点和删除逻辑
- `api/data_pipeline.py` - 数据处理和增量更新逻辑
- `api/git_utils.py` - Git 操作和自动 commit
- `api/dashscope_client.py` - 向量生成和缓存
- `api/vector_db/pgvector_backend.py` - 向量数据库操作
